背景：2026-11-25 TideSong v2.0 已合入主工程，编译 0 错误；双系统分工已定（v2.0 TeamManager/EchoSystem 做实时战斗层，Phase 1 SquadManager/EchoManager 只做养成编队，实机不再重复扣费/加增益）。下面三项是当时留给用户定的，本文把每项的现状、代码位置和推荐默认值写清，用户回一句即可执行。**实机（Play Mode）验证仍未做**，以下三项的改动也需在用户那边进游戏跑一遍。

## 1. 按 1–4 键两套一起切人（最要紧）

**现状（已核对代码）：**

- `unity/Assets/Scripts/Phase1/SquadManager.cs:172–175`：`Update()` 里 `Alpha1–4` → `SwitchTo(0–3)`，花名册是 `SquadData.Roster`：无星者 / 星夜·雪 / 星夜·花 / 月下·凛。
- `unity/Assets/TideSong/Scripts/Team/TeamManager.cs:247–250`：`Update()` 里同样 `Alpha1–4` → `SwitchTo(0–3)`，花名册是 `ResonatorData.All`：Shio / 霜见 / 岚 / 渊（渊需收集 6 声骸解锁）。
- 按一次键，两个 `SwitchTo` 都跑：TeamManager 换共鸣者、触发变奏/延奏；SquadManager 换队员、恢复自己存的 HP/能量、换玩家配色（`ApplyMemberVisual`）、把 AI 队友的扮演角色对调、触发入场/退场技。
- 两边冷却还不一样（`SquadData.SwitchCooldown` vs TeamManager 的 `switchCd`），一边冷却中另一边照样切，两边的 ActiveIndex 会永久错位。

**推荐默认值：TideSong 场景里 1–4 键只归 TeamManager。**

- 做法：给 SquadManager 加一个开关（例如 `public bool HandleSwitchInput = true`，TideSong 的 GameManager 在场景里把它置 false），只关它的按键监听，不动它的编队/养成数据。
- 但这会留一个尾巴：SquadManager 的 AI 队友（1 人操作 + 3 人 AI，见 `SquadManager.cs:2` 注释）原本靠切换对调扮演角色，关掉切换后队友就定在初始扮演的队员上。三个选项：
  - **A（推荐，先这样）**：队友保持初始扮演不变，玩家身份以 TeamManager 花名册为准；改动最小，实机可立即验证。
  - **B**：按 TeamManager 花名册重建 AI 队友——这就是缺失的 C-02，工作量大，单独立项。
  - **C**：TideSong 场景里去掉 AI 队友，纯单人切换（最接近鸣潮手感，但丢了 Phase 1 的小队特色）。

**需用户定一句**：A / B / C。没定之前不要改代码——现在双切虽然乱，但编译通过、两边都不报错。

## 2. SP 没地方花了

**现状（已核对代码）：**

- SP 还在攒：`SquadManager.cs` 的 `AddSP` 还在被调（击杀、受击硬直、入场技 +4、退场技 +2 等），上限 `SquadData.SpMax`（10）。
- 但没人花了：E 键已改成只收 v2.0 的体力+冷却（`TideSong/Scripts/Core/GameManager.cs:185` 注释），`TryUseSkill()` 的 SP 门槛（SP ≥ 3）不再被 E 调用。
- HUD 还在显示：`Scripts/Phase1/SquadHud.cs:145`：`"星律共鸣 X / 100　SP X / 10"`。

**推荐默认值：先把 SP 从 HUD 上藏起来，攒着无害。**

- 做法：`SquadHud.cs:145` 那行只显示共鸣值，一行改动，零玩法风险。
- 改用途（例如 SP 转共鸣能量、SP 换 Q）是数值设计，等养成层设计时再定，现在硬编一个用途反而给以后埋坑。
- 选项：**A（推荐）藏起来** / B 留着显示当 legacy 仪表 / C 现在就定一个新用途（需用户给方向）。
